- 작성일: 2026-10-06
- 요구사항 원본: `PRE-PRD.md`

- 개발 브랜치: `feature/lec09-sonic-animation-viewer`

## 1. 목표

소닉 스프라이트 시트에 포함된 모든 소닉 동작을 확대하여 순서대로 감상하는 뷰어를 만든다. 각 동작은 5회 재생한 뒤 1초 동안 정지하고 다음 동작으로 넘어간다. 마지막 동작이 끝나면 첫 동작으로 돌아가 사용자가 종료할 때까지 반복한다.

한 번에 완성하지 않고 최소 20단계로 나누어 구현한다. 각 단계는 변경 내용을 확인하고 커밋할 수 있는 크기로 구성한다.

## 4. 스프라이트와 프레임 정의

### 4.1 재생 대상

- 시트 상단부터 하단까지 소닉의 동작 행을 순서대로 등록한다.
- 각 동작의 프레임은 왼쪽부터 오른쪽 순서로 재생한다.
- 이미지 제목, 제작자 표시, 설명 문구와 하단의 다른 캐릭터는 소닉 동작에 포함하지 않는다.
- 육안 확인 기준으로 소닉 동작은 10개 행으로 구분된다. 동작 이름은 이해를 돕는 표시용 이름이며, 실제 등록은 행 번호를 기준으로 한다.
- 구현 초기 단계에서 각 행의 프레임 수와 경계를 확인하여 코드에 확정한다. 모든 대상 프레임을 등록했는지 원본 이미지와 대조한다.

### 4.2 프레임 데이터

- 각 동작은 이름과 순서가 있는 프레임 목록을 가진다.
- 각 프레임에는 원본 이미지의 잘라낼 사각형 좌표와 크기를 명시한다.
- 원본 시트는 프레임 간격과 크기가 일정하다고 가정하지 않는다. 머리, 발, 회전 잔상 등 해당 프레임의 요소를 모두 포함하도록 자른다.
- 다른 프레임, 문구, 다른 캐릭터가 잘린 영역에 들어가지 않아야 한다.
- 좌표는 정수이며, 크기는 양수이고 모든 영역은 이미지 경계 안에 있어야 한다.
- 원본을 위쪽 기준으로 측정한다면 pico2d의 아래쪽 기준 좌표로 변환한다. 이미지 높이가 `H`일 때 `bottom = H - top - height`를 사용한다.
- 프레임별 기준점을 맞춰 이미지 크기의 차이로 캐릭터가 불필요하게 흔들리지 않게 한다. 동작 자체에 포함된 자세 변화는 보존한다.

## 5. 기능 요구사항

### FR-01. 시작과 이미지 로드

실행하면 1200 × 800 픽셀의 캔버스를 열고 이미지를 한 번 로드한 뒤 첫 동작의 첫 프레임부터 자동 재생한다. 이미지가 없거나 로드에 실패하면 원인과 대상 경로를 콘솔에 출력하고 종료한다.

### FR-02. 확대 출력

프레임의 원본 가로·세로 비율을 유지하며 각각 4배로 그린다. 모든 프레임이 캔버스 안에 표시되어야 한다. 프레임 크기가 달라져도 동작의 기준 위치는 유지한다. 배경은 소닉과 구별되는 단색으로 지정하고 원본의 투명 영역을 유지한다.

### FR-03. 프레임 재생

현재 동작의 프레임을 설정된 재생 속도로 순서대로 표시한다. 초당 프레임 수는 양수이며, 구현 시 각 동작을 알아보기 쉬운 값으로 결정한다. 프레임 속도는 코드의 상수 한 곳에서 조정할 수 있어야 한다. 실제 경과 시간을 사용하여 화면 갱신 횟수에 따라 재생 속도가 달라지지 않게 한다.

### FR-04. 동작별 5회 반복

첫 프레임부터 마지막 프레임까지 각각 지정된 시간 동안 표시하면 1회 재생으로 계산한다. 마지막 프레임에 도달한 순간이 아니라 마지막 프레임의 표시 시간이 끝난 시점에 횟수를 증가시킨다. 1~4회 완료 후에는 같은 동작의 첫 프레임으로 돌아간다. 5회 완료 후에는 정지 상태로 전환한다.

### FR-05. 1초 정지

5회 재생이 끝나면 해당 동작의 마지막 프레임과 표시 위치를 1초 동안 유지한다. 정지 중에는 프레임과 반복 횟수를 변경하지 않는다. 창 이벤트 처리와 화면 갱신은 계속하여 즉시 종료할 수 있어야 한다. 이벤트 처리를 막는 1초짜리 대기 호출로 구현하지 않는다.

### FR-06. 다음 동작과 전체 순환

정지 시간이 끝나면 다음 동작의 첫 프레임으로 전환하고 해당 동작의 완료 횟수와 시간 누적값을 초기화한다. 마지막 동작의 정지가 끝나면 첫 동작으로 돌아가 같은 규칙을 계속 적용한다.

### FR-07. 종료와 자원 정리

재생 또는 정지 중에 ESC나 창 닫기 이벤트가 발생하면 반복을 종료하고 캔버스를 닫는다. 정상 실행 중 오류가 발생한 경우에도 열린 캔버스를 정리한다.

## 6. 상태와 시간 처리

필요한 재생 상태는 다음과 같다.

| 상태값 | 의미 |
| --- | --- |
| 현재 동작 인덱스 | 재생할 동작의 순서 |
| 현재 프레임 인덱스 | 해당 동작에서 표시할 프레임 |
| 완료 횟수 | 현재 동작을 끝까지 재생한 횟수, 0~5 |
| 재생 상태 | `PLAYING` 또는 `WAITING` |
| 프레임 누적 시간 | 다음 프레임 전환을 판단할 경과 시간 |
| 정지 누적 시간 | 1초 정지 종료를 판단할 경과 시간 |
| 실행 여부 | 메인 반복문 종료 판단 |

동작의 프레임 수가 `N`, 프레임당 표시 시간이 `T`이면 동작 재생 시간은 `5 × N × T`이고 이후 1초 정지가 이어진다. 초당 프레임 수가 `F`이면 `T = 1 / F`이다. 재생 속도를 변경해도 5회 반복과 이후 1초 정지 규칙은 유지한다.

시간 갱신이 프레임 경계를 여러 번 지나면 누적 시간에 맞춰 필요한 전환을 처리한다. 정지 상태로 진입하거나 다음 동작으로 넘어가는 경계에서도 시간을 중복 계산하지 않는다. 시간 오차의 허용 범위는 정상 실행 환경에서 화면 갱신 1회에 해당하는 시간으로 한다.

## 7. 범위

이번 구현은 자동 재생과 종료에 집중한다. 동작 선택 UI, 재생 속도 조절 UI, 사운드, 게임 조작, 캐릭터의 화면 이동, 점프 궤적, 이미지 편집과 실행 파일 패키징은 요구하지 않는다.

## 8. 단계별 개발 및 커밋 계획

각 단계는 이전 단계의 실행 가능한 결과를 확장한다. 단계마다 변경 사항과 확인 결과를 기록하고, 확인을 통과하면 별도 커밋으로 남기는 것을 기본 절차로 한다. 완료된 동일 코드를 나누어 형식적인 커밋만 만드는 방식은 사용하지 않는다.

| 단계 | 구현 내용 | 확인 기준 |
| --- | --- | --- |
| 01 | 단일 Python 실행 파일과 시작점 작성 | 문법 검사 통과 |
| 02 | 1200 × 800 캔버스 열기와 닫기 | 지정 크기의 창이 정상적으로 열리고 닫힘 |
| 03 | 메인 반복문과 창 닫기 이벤트 처리 | 창 닫기로 반복 종료 |
| 04 | ESC 종료 처리 | ESC로 캔버스 정리 |
| 05 | 파일 위치 기준 이미지 경로와 로드 | 다른 작업 디렉터리에서도 이미지 로드 |
| 06 | 로드 실패 처리 | 누락 이미지의 경로와 오류가 표시됨 |
| 07 | 동작 행과 프레임 목록 조사·데이터 형식 확정 | 모든 소닉 동작의 프레임 수 기록 |
| 08 | 첫 동작의 첫 프레임 잘라 그리기 | 캐릭터와 잘린 영역 대조 |
| 09 | 4배 확대와 단색 배경 적용 | 비율 유지, 캐릭터 식별 가능 |
| 10 | 첫 동작의 전체 프레임 좌표 등록 | 누락·잘림·인접 프레임 혼입 없음 |
| 11 | 첫 동작의 시간 기반 프레임 재생 | 설정된 프레임 시간으로 순서 재생 |
| 12 | 동작 2~3의 프레임 등록 | 두 행의 원본과 재생 대조 |
| 13 | 동작 4~5의 프레임 등록 | 두 행의 원본과 재생 대조 |
| 14 | 동작 6~7의 프레임 등록 | 두 행의 원본과 재생 대조 |
| 15 | 동작 8~10의 프레임 등록 | 전체 소닉 동작 등록 완료 |
| 16 | 프레임별 표시 기준점 보정 | 불필요한 위치 흔들림과 화면 잘림 없음 |
| 17 | 재생 완료 횟수 계산 | 마지막 프레임 표시 시간 이후 1회 증가 |
| 18 | 같은 동작의 5회 반복 구현 | 5회 재생 후 추가 반복 없음 |
| 19 | 정지 상태와 마지막 프레임 유지 | 정지 중 프레임 변경 없음 |
| 20 | 1초 정지 시간과 정지 중 이벤트 처리 | 정지 시간 준수, ESC·창 닫기 즉시 처리 |
| 21 | 다음 동작 전환과 상태 초기화 | 다음 동작이 첫 프레임·0회부터 시작 |
| 22 | 마지막 동작에서 첫 동작으로 순환 | 전체 순환이 두 번 이상 이어짐 |
| 23 | 시간 경계·좌표·자원 정리 검증 및 보완 | 경계 오차, 잘못된 좌표, 종료 오류 없음 |
| 24 | 전체 실제 실행 검증과 결과 기록 | 아래 완료 기준 모두 충족 |

커밋 메시지는 한글로 작성하고 실제 변경 내용을 설명한다. 파일명과 코드 식별자는 원문을 유지할 수 있다. 예: `캔버스 생성과 종료 처리 구현`, `동작별 5회 반복과 1초 정지 구현`. 각 단계 보고에는 단계 번호, 변경 요약, 확인 방법과 결과, 커밋 식별자를 포함한다. 실패한 확인 항목은 통과한 것으로 기록하지 않는다.
